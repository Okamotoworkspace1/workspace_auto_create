# 素材を揃える

1 本分の画像・映像を集める手順です。所要 30 分〜1 時間。

このマニュアルは `examples/basketball` の道具（`catalog.tsv` / `catalog.py` /
`fetch.py`）を前提にしています。チャンネルごとに同じ構成で作ってください。

---

## 原則

**優先順位を固定します。迷ったらこの順です。**

1. **一次資料**（記録・公式文書・公的機関の写真）— 最も強く、権利も軽い
2. **自由ライセンスの実写** — Wikimedia Commons
3. **自作の図解** — 数字だけ。探してこられないものに限る
4. **汎用 b-roll** — Pexels / Pixabay。つなぎ
5. **生成画像** — 最後の手段。人物・ロゴ・日本語は作れない

生成画像だけで組むと、どのチャンネルでも作れる映像になります。
**実在の人物・記録を最低 2〜3 枚は混ぜてください。**

---

## Step 1. 必要な絵を洗い出す

台本を 8〜10 カットに割り、カットごとに「何を映すか」を 1 行で書きます。

```
1  0:00-0:08  掴み。誰もいない会場に一筋の光
2  0:08-0:18  記録が古びる感じ
3  0:18-0:24  問いの間
...
```

**ここで具体的な写真を決めないでください。** 「何を映すか」だけです。
手に入るものは後で分かるので、先に絵を決めると探し直しになります。

---

## Step 2. 手持ちを引く

```bash
cd examples/<チャンネル>/assets
python3 catalog.py ロッドマン      # ラベル・タグ・メモの部分一致
python3 catalog.py --kind 動画
```

過去の回で登録したものが当たれば、探す工程は飛ばせます。
**回を重ねるほどここで終わるようになります。**

---

## Step 3. 無いものを探す

### 3-1. まず公的機関を当たる（最重要）

スポーツ選手の写真は NBAE / Getty 管理で手が出ませんが、
**公的機関が撮った写真は別系統でパブリックドメインです。**

- **優勝チームのホワイトハウス訪問** — 米政府職員の職務著作＝ PD。
  帰属義務も継承もなし。1996年ブルズはこれで優勝メンバー全員が揃いました
- 軍・NASA・議会の行事、公的な式典

検索語の型：

```
Wikimedia Commons <チーム名> White House visit <年> public domain photo
```

**これが当たると後工程が全部軽くなります。** 最初にここを叩いてください。

### 3-2. 一次資料を探す

公式記録・スコアシート・プログラムは、選手写真より強く、見落とされています。

```
Wikimedia Commons <大会名> official scorer's report <年>
```

1996年ファイナル第6戦の公式スコアシートはこれで見つかりました。

### 3-3. カテゴリから掘る

Commons は検索より**カテゴリを開くほうが速い**です。

```
https://commons.wikimedia.org/wiki/Category:<人名>
https://commons.wikimedia.org/wiki/Category:1995–96_NBA_season
```

カタログの `種別 = カテゴリ` の行が掘り口として登録してあります。

### 3-4. 汎用 b-roll

- [Pexels](https://www.pexels.com/search/videos/basketball/) / [Pixabay](https://pixabay.com/videos/search/basketball/)
- 帰属不要・商用可。選手は写らないので、つなぎ専用

---

## Step 4. カタログに登録する

`catalog.tsv` に 1 行足します。列は
`ID / ラベル / タグ / 年 / 種別 / ライセンス / 継承 / URL / 確認 / メモ`。

```
bulls96-wh-1	1996年優勝ブルズ ホワイトハウス訪問	ブルズ,1996,ジョーダン,集合,人物	1997	写真	PD-USGov（要確認）	なし	https://commons.wikimedia.org/wiki/File:...	未	★優勝メンバーが一枚に
```

- **URL はファイルページ**（`.../wiki/File:...`）。画像の直リンクではありません
- **タグは日本語でカンマ区切り。** 人名・チーム・年代・用途を入れると後で引けます
- **継承** は `あり` / `なし` / `要確認`。CC BY-SA は `あり`
- **確認** はファイルページを開くまで `未`
- **年代が題材と合わない素材は、メモにその旨を書く**。後で事故ります

---

## Step 5. まとめて落とす

```bash
python3 fetch.py                 # カタログ全件
python3 fetch.py ブルズ           # 部分一致で絞る
python3 fetch.py --full          # 縮小せず原寸
```

`downloads/` に `<ID>.<拡張子>` で入ります。gitignore 済みなので
リポジトリは太りません。

**幅は標準サムネイル幅から選んでください**（320 / 640 / 800 / 1024 / 1280 / 2560）。
ここに無い幅を頼むと Wikimedia 側で毎回レンダリングが走り、
429 Too many requests で弾かれます。既定の 2560 は、横位置の写真を
縦 1080×1920 に切る前提で選んでいます。

429 が出たら 5 / 15 / 45 秒で 3 回まで自動再試行します。
それでも落ちなければ時間を空けるか、ブラウザで手動保存してください。

### PDF は画像にする

```bash
pdftoppm -png -r 150 -f 1 -l 1 downloads/<名前>.pdf downloads/<名前>
```

## Step 6. 埋まらないカットを生成で補う

`assets/prompts/<回>.md` に例があります。

**生成では作れないものが 3 つあります。**

| 作れない | 理由 | どうするか |
|---|---|---|
| 実在人物 | 画像生成は実在人物の肖像を作らない。作れても肖像権が残る | 実写を使う |
| チームのロゴ・ユニフォーム | 商標 | 無地で生成し、記号はテロップで足す |
| 日本語のテロップ | 文字が崩れる | 編集ソフトで乗せる |

**人物が要るカットは実写、雰囲気をつなぐカットだけ生成**という切り分けです。

### プロンプトの型

**共通のスタイル指定を全カットの先頭に付けます。** これが無いと
8 枚が別々の動画のように見えます。

```
Cinematic still, vertical 9:16 aspect ratio, <時代と場所>.
Shot on 35mm film, warm tungsten lighting, deep shadows, fine film grain,
muted palette of <色を2〜3色>. Shallow depth of field.
No faces, no text, no numbers, no logos, no brand marks.
Keep the lower third dark and uncluttered so subtitles stay readable.
```

最後の 1 行は字幕の場所を空けるためです。忘れると読めなくなります。

1 カットにつき 3〜4 枚出して選んでください。1 枚目が当たることは稀です。

生成したら `種別 = 生成` でカタログに足しておくと次回使い回せます。

## Step 7. 公開前に確認する

**1 本目は出してしまって構いません。** 気になったらここに戻ってください。

```bash
python3 catalog.py --todo     # ライセンス未確認のものを並べる
python3 catalog.py --no-sa    # 継承なしだけ（収益化向き）
```

- [ ] 使った素材のファイルページを開き、**著作者名・ライセンス・現存**を確認して `確認 = 済` にする
- [ ] **著作者名は推測で埋めない。** ファイルページの「作者」欄をそのまま写す
- [ ] CC BY-SA を使うか決める（下記）
- [ ] 年代が題材と合っているか（引退後の写真を現役時代の話に使っていないか）
- [ ] ロゴを使っていないか（商標。サムネイルでは特に避ける）
- [ ] 概要欄にクレジットを貼る

### CC BY-SA の継承

画像を動画に組み込んだものが「二次的著作物」と評価されると、
**動画全体を同じ CC BY-SA で公開する義務**が生じ得ます。
解釈が割れており、判例で固まってはいません。避けるなら 3 択です。

1. **使わない。** `catalog.py --no-sa` の範囲＋自作図解で組む
2. **継承を受け入れる。** 概要欄で動画を CC BY-SA として明示する
3. **権利者から直接ライセンスを得る。** 個別交渉が最も安全

法務リスクの取り方なので、チャンネルの方針として一度決めてください。

### クレジットの書き方

CC BY-SA は**著作者名・ライセンス名・ライセンスへのリンク**の 3 点が必須です。

```
【画像クレジット】
<被写体と年> — <著作者> / Wikimedia Commons — CC BY-SA 3.0
  https://creativecommons.org/licenses/by-sa/3.0/
<被写体> — White House photo / Wikimedia Commons — Public Domain
b-roll: Pexels / Pixabay
図解：本チャンネル制作（出典 <データの出所>）
```

パブリックドメインは義務ではありませんが、書いておくと後で追えます。

## やらないこと

**キーワードから素材を機械的に割り当てるのは失敗しました。**

台詞に含まれる語（「審判」「記録」「背番号」）で素材を自動で当てる仕組みを
一度作りましたが、文脈を無視した割り当てになり使い物になりませんでした
（「審判と揉め」にロッドマンの顔写真、「破られていない記録」に別の回の棒グラフ）。

**カットへの割り当ては人がやってください。** 機械にやらせるのは
「探す」「落とす」「記録する」までです。

## 2 本目以降

1 本ごとに `catalog.tsv` が育ちます。Step 2 で当たる割合が上がり、
Step 3 が短くなっていきます。

- 使わなかった素材も登録しておく（次の回で当たる）
- 生成画像も登録する（`種別 = 生成`）
- 探して見つからなかったものはメモに残す（同じ検索を繰り返さない）
